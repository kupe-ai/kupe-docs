## Hosts

| | Milli | Kupe |
| --- | --- | --- |
| REST | `https://api.kupe.in` | `https://x.kupe.in` |
| Console | Legacy app | `https://hub.kupe.in` |
| Docs playground | — | Sends Try it to `https://x.kupe.in` |

Milli local default was `http://localhost:5050`. Kupe local/dev still uses `KUPE_BASE_URL` if you override; production SDKs default to `https://x.kupe.in`.

Do **not** put `/v1` in `KUPE_BASE_URL`. Paths in this site are `{base}/v1/...`.

## Auth header

Milli accepted either:

- **`x-api-key: <opaque>`** — server-generated `secrets.token_urlsafe(32)`, user-scoped, optional path-prefix ACLs.
- **`Authorization: Bearer <Supabase JWT>`** — dashboard session.

Kupe accepts a **single** header on every `/v1` route:

```
Authorization: Bearer sk-kupe-YOUR_KEY
```

Project keys start with `sk-kupe-` and are scoped to **one org and one project**. Hub sessions may send a Supabase user JWT instead (`auth: jwt` on `GET /v1/me`). Voice **clone / patch / delete** require JWT. See [Authentication](/auth).

Milli keys are **not** valid on `x.kupe.in`. Create a new key in Hub: **project → API keys**.

<CodeGroup>

```bash Milli
curl https://api.kupe.in/api/v1/agents \
  -H "x-api-key: YOUR_MILLI_KEY"
```

```bash Kupe
curl https://x.kupe.in/v1/me \
  -H "Authorization: Bearer sk-kupe-YOUR_KEY"
```

```python Python
from kupe import Kupe

client = Kupe()  # KUPE_API_KEY
me = client.me()
# {"auth": "api_key", "org_id": "org_...", "project_id": "prj_...", ...}
```

```typescript TypeScript
import { Kupe } from "kupe-sdk";

const me = await new Kupe().me();
```

</CodeGroup>

## Identity model

| Milli | Kupe |
| --- | --- |
| Almost everything is **user-scoped** (`request.state.user.id`) | API keys are **org + project**. Nested routes need `org_id` and often `project_id`. |
| `GET /api/v1/me` returns the Milli profile / consent / org context | `GET /v1/me` returns `auth`, `org_id`, `project_id`, `user_id`, `api_key_id` |
| Org admin can act on other users via query `user_id` | Members are `GET/POST /v1/orgs/{org_id}/members`. Keys cannot impersonate another project. |
| `POST /api/v1/api-keys` creates a user key | `POST /v1/projects/{project_id}/api-keys` |

Resolve IDs once, then reuse them:

```bash
curl https://x.kupe.in/v1/me \
  -H "Authorization: Bearer sk-kupe-YOUR_KEY"
```

## CORS and `create_call`

Milli `POST /api/call/create_call` is on the auth **exclude** list (middleware skips JWT/`x-api-key`), then the handler resolves identity itself (`x-api-key` or Bearer) **and** rejects unknown `Origin` via `validate_origin`. Browser apps had to be on the CORS allow-list (`api.kupe.in` plus verified custom domains).

Kupe outbound is a normal authenticated `/v1` route. Send the Bearer key; there is no Origin gate on the public API the way Milli implemented `create_call`.

## Public vs provider webhooks

Milli left telephony answer URLs unauthenticated on purpose (`/api/call/incoming_call`, `/api/call/plivo-incoming_call`, `/api/call/plivo-hangup`, Exotel/Elison variants). Kupe does the same for **provider** callbacks (`/v1/telephony/plivo/inbound`, `/v1/plivo/webhooks/ucc`, …). Those paths are **not** in the public OpenAPI and you should not call them from your app — Plivo/Twilio/Exotel call them.

Your app should only call documented `/v1/...` routes with a Bearer key.
